## Post-review follow-up fixes & sealed evaluation findings

- **Confirmed employee vs. ranking tie (`orchestrator.py` + `router.py`):** Even when an employee was already confirmed (`last_subject_employee_id` on prior context or resolved via `clarification_choice_id` / explicit name), `get_agent_spotlight_and_trend` still populated `spotlight["ties"]` for same-score peers, causing follow-ups without `clarification_choice_id` or the employee's name repeated (e.g. `"What is her score?"`) to clear `last_subject_employee_id` and re-ask which person. `orchestrator.py` now preserves `already_confirmed_employee`, keeps `resolved_state.employee_id` synced, and `router.py` keeps substantive prompts intact when applying `clarification_choice_id` while restoring `prompt_to_send` on selection-only or partial-name tokens.
- **Operation & metric independence (`router.py`, `domain_policies.py`, `tool_registry.py`, `providers.py`):** `"Summarize this person's score pattern across the available months."` and `"What was their trend?"` previously leaked `outbound:bookings_count`, forced person follow-ups with `"trend"` to `current_value`, and short-circuited in `providers.py` to single-month bookings. Added explicit overall-score detection (`_is_explicit_overall_score_request`), `kpi_history` extraction across months in `tool_registry.py`, true multi-period trend headlines/bullets (and explicit insufficient-history disclosure when `< 2` periods exist), and fixed `"booking-rate"` vs. `"how many ... bookings"` matching (`v2_05_t4`) as well as correction rejection phrases (`v2_05_t3`).
- **Country formatting URL safety (`orchestrator.py`):** `_apply_country_display` now protects Markdown link destinations and standalone URLs/routes/query parameters and prevents duplicate `· UAE` / `· Egypt` suffixes.
- **Frontend compile blocker resolved:** `Frontend/src/features/monthlyPresentation/components/TeamDeepDiveView.tsx:2711` now passes `matchedKpi?.movementFormatted || null` instead of nonexistent `matchedKpi?.trendLabel`, and `npx tsc --noEmit` exits cleanly (`0`).
- **Strict evaluator & sealed blind final eval:** `Backend/scripts/run_unseen_eval.py` (`validate_turn_response`) now validates `expected_intent`, `expected_metric`, multi-period mentions, and movement/insufficient-history evidence; `ai_response_quality_holdout_v2.json` is explicitly labeled exposed regression coverage (`16/16` dev, `16/16` exposed heldout). After implementation completed, a brand-new 32-prompt / 8-conversation blind set (`Backend/tests/fixtures/ai_response_quality_final_blind_eval.json`) scored **27/32 (84.38%)** on its unedited first run without tuning; all 5 blind failures (`b04_t2`, `b04_t3`, `b04_t4`, `b05_t2`, `b08_t3`) remain honestly reported as remaining gaps (`"Switch to Egypt instead."` routing gate, `"Summarize <Name>'s ..."` possessive extraction stopword, single-person non-booking KPI current-value display in `providers.py`, plus `b05_t2` display label `"Rejection Rate"` vs. expected `"Controllable Rejection Rate"`).
